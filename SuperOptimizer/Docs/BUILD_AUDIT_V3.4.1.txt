BACKUP / ROLLBACK
- Registro: backup original antes da mutação; leitura pós-escrita; Binary/MultiString suportados.
- Serviços: backup Start/DelayedAutoStart/Running antes da mutação; restauração verificada.
- Tarefas: estado Enabled salvo antes de desativar; restauração verificada.
- Hibernação: não altera sem estado original explícito.
- Defender: não altera sem backup da preferência.
- Energia: plano original salvo antes de criar/ativar o plano Gaming.
- VBS/HVCI/BCD: backup completo da camada antes de alteração crítica.
- StateAudit: JSON + identidade canônica de Registry/Services/Tasks.

PERFIS
- Universal: restaura camadas agressivas/extremas gerenciadas e reaplica apenas o núcleo universal.
- Agressivo: remove a camada VBS/Extrema gerenciada antes de aplicar o Agressivo.
- Extremo: Agressivo + VBS/HVCI/Hypervisor OFF com backup crítico.
- Ponto de restauração marcado pelo usuário é obrigatório: se falhar, o perfil não prossegue silenciosamente.
- Políticas secundárias de background são best-effort e viram avisos, não abortos indevidos.

MANUTENÇÃO / LIMPEZA
- Fail-safe aceita somente raízes explícitas TEMP, Windows Temp, D3DSCache e SoftwareDistribution\Download.
- Reparse points/junctions são ignorados.
- Acesso Rápido/Recent não é limpo.
- Prefetch não é limpo.
- Event Logs não são limpos.
- Lixeira é ação separada.
- Shader cache é ação separada.
- DISM/SFC não fazem parte da rotina semanal.

WINDOWS UPDATE
- Stop temporário guarda WasRunning.
- Snapshot vazio/duplicado/inesperado é recusado.
- Falha parcial ao parar serviços tenta rollback automático.
- Cache Update restaura o estado anterior no finally.
- Rollback geral não inicia serviços de Update sem snapshot prévio.

RAM
- EmptyStandbyList é opcional e não é distribuído.
- Uso automático em perfis/manutenção semanal: bloqueado.
- Validação estrutural MZ, SHA-256 e Authenticode status.
- HashMismatch é recusado.
- Timeout de 30 segundos por comando.
- Limpeza completa exige confirmação explícita.

CONCORRÊNCIA / IPC
- UI bloqueia segunda operação ativa.
- Worker usa lock exclusivo entre processos para operações mutáveis.
- Cada rota deve retornar exatamente um resultado estruturado.
- WarningCount/WarningMessages seguem no resultado.
- Progresso da UI não pode abortar a operação real.

- ferramentas nativas/cmdlets
